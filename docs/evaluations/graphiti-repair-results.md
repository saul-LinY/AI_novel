# Graphiti 修复及复测

日期：2026-10-14。结论：旧持有关系能够结束，归还产生独立新区间；冻结存档的精确原文证据命中由 3/12 提升到 11/12，无原已命中项目退步。

## 修改

- 持有/位置先经模型识别和逐字引文、实体引用校验，再由程序维护单值区间与否定更新。旧原生支持关系也补上对应有效期；反复归还不会复用旧区间。
- 查询聚焦当前行动/问题；关键词候选与图候选进入同一本地 INT8 中文重排模型。长段落按逐字片段精排，避免只截取段首，也不再靠重复命中投票把背景资料抬到直接证据前面。
- 旧图按来源回合逐步补齐，区间和完成标记使用同一 Neo4j 事务。修复过程或服务异常时保留本地记忆。

## 时效与条件句

真实模型调用后读取 Neo4j 的结果：

| 时间段（故事逻辑时间） | 钥匙持有人 | 状态 |
| --- | --- | --- |
| 第 0～5 分钟 | 许川 | 已结束 |
| 第 5～10 分钟 | 顾宁 | 已结束 |
| 第 10～15 分钟 | 许川 | 归还后新区间，随后放下结束 |
| 第 15 分钟起 | 无当前人物持有断言，位置为木匣 | 计划移到桌上没有提前生效 |

首次“许川唯一持有钥匙”的原生 Graphiti 关系也从 valid_at=null/invalid_at=null 修正为第 0 分钟开始、第 5 分钟结束。归还后新状态有不同 ID，不会复活第一次持有记录。

放入木匣后持有关系结束，位置区间建立；随后只提出移动计划，原位置区间 ID 和开始时间均不变。对照结果见 [交接数据](graphiti-repair-after.json) 与 [位置及计划数据](graphiti-repair-location-plan.json)。

## 运行与限制

154 项 JavaScript 测试和 20 项 Python 测试通过。正式存档的 14 个视角完成有效期补齐。另用当前真实存档进行四视角召回：4424 ms，四个视角均使用 cross_encoder 且没有退回 BM25，找回了“最后一支药塞进外侧口袋”的原文。[运行样本](graphiti-repair-runtime.json)

精排增加了耗时，本次单全局测试约 0.9～3.0 秒，四视角样本约 4.4 秒；配置等待预算为 5 秒，超时仍回退。模型仍可能漏识别实体、指代和状态变化；程序保证已接受断言的区间一致性，并不保证自然语言理解永远正确。所有新增测试剧情使用独立图，没有向正式小说提交测试回合。
