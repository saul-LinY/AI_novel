# 当前故事生成与记忆闭环

依据 2026-10-14 的本地运行代码与配置核对。控制台入口：`http://127.0.0.1:4318/?view=workflow`。

1. 玩家行动创建回合作业。读取当前分支头事件、世界状态、最近四段开场/正式回合及角色、环境、分支摘要。
2. 在新回合生成前检索历史记忆：按分支、截止回合、人物知情范围筛选；BM25 先召回候选，Graphiti 补充图关系和语义候选，按向量相似度与关键词名次融合。原文、来源事件、内容哈希和快照要匹配。图索引未就绪或服务失败时使用本地结果。
3. 对自由行动做角色秘密词预检；通过后将上下文分发给情节、人物、环境三个并行 agent。人物记忆保留各自视角，不能跨人物共享秘密。
4. 主创汇总报告，提出结果、状态变化、节拍、伏笔和选项。结构、因果、知识边界及选项规则必须通过。节奏/伏笔检查在当前 enforce 配置下退回一次，仍未修正时记录警告放行。各结构化调用连续三次硬校验失败停止该调用，记录员失败可走确定性兜底。
5. 通过提案后保存 prepared，锁定结果与场景；主创依据写作简报逐句输出。检查重复、长度等质量问题，必要时补写或记录警告。当前选项是 inline，与提案一起生成；若配置为 parallel，则独立生成选项，记录员可与尚未结束的选项任务并行。
6. 记录员结合已发布正文、提案、实体目录和旧账本抽取连续性记录。事实引文必须逐字存在于正文；超时或失败有确定性兜底。它不能重写玩家已看到的正文。
7. 再次确认分支头没有变化，保存正文、状态变化、叙事账本和记忆。此后玩家可进入下一轮。
8. 保存成功后分别异步更新 BM25 和 Graphiti。Graphiti 通过持久队列抽取实体关系、生成向量并校验持有者/位置的有效时间，存入 Neo4j；供后续回合检索和历史查询使用。

## 需要准确表达的边界

- 游戏存档是世界状态的权威来源；Neo4j 是由已提交故事派生的记忆图。当前没有将 Neo4j 手动编辑反向同步到游戏存档的机制。
- Graphiti 当前专项时间状态投影覆盖持有和位置；其他关系可以被抽取，但不代表所有人物属性、物品状态都已具备同等严格的转换规则。
- “回合完成”“记忆快照已入队”“图索引完成”是三种不同事实。工作流图展示本轮保存的入队记录，索引最新进度到回合记忆页查看，不能用最新状态冒充旧回合当时的完成情况。
- 行动不成立与技术失败分别显示。前者允许修改行动；后者保留实际失败步骤，已准备正文的暂时中断可续写。
- 正文在记录和提交之前已经流式展示；“确认保存 / 下一轮”不应画成正文首次出现的位置。
- 无运行记录时显示流程说明，不伪造各节点已完成。旧回合缺失的检索/入队记录标为未记录。

## 实现入口

- `src/server.js`：回合作业、检索、保存与异步入队。
- `src/pi-story-runtime.js`：知识预检、并行分析、提案校验、写作、续写、记录。
- `src/memory/story-memory.js`：分视角检索、合并重排与本地降级。
- `services/graphiti/app.py`、`state_projection.py`：队列、图检索、Neo4j 和状态时间区间。
- `src/console-server.js`、`console/app.js`：运行记录与工作流呈现。
