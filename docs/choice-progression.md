# 选项推进与正式结局

推荐选项此前只检查数量与动作是否合法，没有要求目标和后果。最后阶段已经完成的存档也仍能接续回合，导致正文反复收尾后继续推荐吃饭、看风景、安静陪伴。

## 生成规则

情节与主模型现在收到玩家已知且未解决的线索标题、实际目标进度、已知事实，以及最近回合的行动和选项。每个推荐行动都需要具体对象和手段，争取能改变局面的证据、表态、资源、路线或保护结果；至少两种行动方式。已经作出的决定应推进到执行，日常互动只有触及具体冲突时才可推荐。不得凭空制造袭击、复活已解决危机或预定玩家成功。

主模型在 `prepare_story_turn` 中为选项提供内部 `choicePlan`，标明目标、方式、可能变化和代价。`validateMainProposal` 先预演本回合状态，再校验目标是否仍然可用、计划与选项是否逐项匹配、行动是否重复、方式是否多样。工具返回失败时由模型修正，校验通过后才开始正文流，不撤回或改写已展示正文。计划不通过公开接口返回，也不添加到按钮文案。

这些程序检查保障目标引用与结构一致性；不能仅凭元数据证明文学效果，也不能识别所有语义近似的改写。冲突是否自然、取舍是否有趣仍依靠生成规则和真实模型样本评估。

## 收尾

新回合完成最终阶段时必须同时提交 `ending` 并清空选项。结局应交代选择、后果与未解问题，非结局正文不得宣告整篇完结。已完成阶段不再重复写入完成证据，保持旧存档与事件重放兼容。

已结束状态在阅读页展示落幕印章和结局摘要，隐藏输入及选项；封面提供“重温故事”。后端在创建作业前以 HTTP 409 拒绝已结束存档的新行动，避免刷新或直接请求继续生成。

## 验证

- `npm test` 覆盖缺失推进计划、已解决或未知目标、重复行动与整组选项、方式缺乏差异、最终阶段收尾、公开接口隔离，以及已完结存档不创建作业。
- `test/immersive-ui.mjs` 使用隔离临时存档验证结局在桌面与 320px 界面显示、刷新回看和输入收起，不触碰默认存档。
- `dogfood-output/choice-policy-20260909/live-samples.json` 保存两回合真实模型输出。以陪伴吃早餐开局，后续选项涉及撤离条件、血清药源、追踪检查及承担行程代价，阶段随行动推进；这只是短程样本，不能代表长篇游玩的全部质量。
