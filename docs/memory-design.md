# 三层长期记忆：本地 BM25

更新日期：2026-09-29。记忆写入、检索和观察统一使用本地文件与 BM25，不依赖网络、密钥、额外模型或数据库服务。小说生成继续使用原来的 Pi 模型链路。

## 事实来源与三层视角

1. **全局记录**：已提交的 `event.json`、`stateAfter` 和故事包是权威来源。完整正文分段、事实、回合结果、状态变化和明确备注组成可重建的记忆卡。尚未采纳的提案、NPC 意图和失败回合不当作已发生事实。
2. **角色认知**：角色只获得显式的角色记忆、在对应回合知晓的事实，以及自己的状态和关系变化。同场出现不自动分享秘密；角色的误解与全局事实分别保留。
3. **当前回忆**：根据行动、地点、当前目标查找相关卡片；先按故事、安装实例、存档历史和角色筛选，再建立词频统计并排名。全局和环境资料分别交给对应 Agent。

当前状态始终单独提供。记忆检索不能修改物品、生死、路线或角色知识。全局原文可追溯，不代表每个角色都会自动理解原文中的全部细节。

## 写入与恢复

- 成功提交回合后，在后台把卡片写入 `.ai-novel/memory/bm25/`。
- 通过临时文件和原子替换更新索引；相同内容不重复写入。
- 索引丢失或内容损坏，可根据原始事件重新构建。回执保存在 `memory/checkpoints/`，不把回执单独当作实际入库证据。
- 索引未追上时，查询仍直接使用当前已提交的卡片。前台无需等待后台索引。

## 查询规则

- BM25 参数：`k1 = 1.2`，`b = 0.75`；使用中文分词，复合词字对权重为 `0.2`。
- 人物名称、ID、显式别名共用实体词项，同时保留原文词语。歧义别名不擅自映射。
- 检索结果再次核对卡片 ID、内容哈希、来源事件和原文，拒绝越权、未来回合、其他分支和过时内容。
- 默认每个视角最多 5 条，所有视角正文总预算 6000 字符；来源标签不计入正文预算。
- 意外检索失败或结果校验失败时，保留角色边界，用原有本地关键词规则兜底并记录失败。
- 所有新调用保存 `backend: bm25`、查询、耗时、降级原因和每个视角的数量；命中结果包含命中词。

## 模块

- `cards.js`：从已提交事件生成带来源、角色和历史范围的卡片。
- `bm25.js`：中文分词、显式别名、BM25 排序与命中词。
- `bm25-backend.js`：本地索引持久化、原子替换和词项索引缓存。
- `story-memory.js`：权限、历史截断、后台同步、召回预算及结果验证。
- `console-memory.js`：只读构建每轮的新增、累计和实际调用记录，并核对本地索引。
- `scripts/memory-local.js`：配置、自检、状态与索引重建。
- `scripts/evaluate-bm25.js`：禁止网络的量化评估；测试数据独立于生产存档。

## 控制台与历史

控制台按选定回合截断历史，不把之后发生的事显示到此前回合。累计条目与调用条目分开；旧调用记录按原始方式展示，不因后来改变检索方式而重写历史。作者视角可见隐藏设定，但这不代表角色知情。

## 测试与限制

测试覆盖中文分词和别名、角色/分支隔离、来源核验、索引重启与重建、写入失败恢复、历史展示和零网络请求。量化评估使用 80 个虚构回合、403 条卡片、48 条中文问题，并报告所有未命中项。详见 [BM25 评估](evaluations/memory-bm25-evaluation.md)。

BM25 依赖词语关联，可能漏掉抽象转述、隐含因果和缺少共同词语的问题。测试结果不是所有小说情境的质量保证，也不能证明生成模型永远不会臆造。
